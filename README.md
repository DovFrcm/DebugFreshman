# STM32F103C8 智能小车：OLED 多级菜单 + 4 路灰度巡线 + 串口（裸机）

一块 STM32F103C8T6「Blue Pill」加小车底板，不用标准外设库、不用 HAL，
只靠 `User\board.h` 里手写的寄存器定义把整套东西跑起来：
**128×64 OLED 中文菜单**、**TB6612 双电机 PWM 驱动**、**4 路灰度循迹（PD + 元素状态机）**、
**9600 波特率的上位机串口**。上电直接进主菜单，所有功能都能用板载 + 外接的 4 个按键操作。

**工程根目录：`F:\Stm32\Project`**（`1.uvprojx` 就在这一层，用 Keil 或 VSCode 打开它）。

## 1. 接线

### 1.1 需要的东西

Blue Pill 一块、**小车主板**（带 TB6612 电机驱动、OLED 座、蜂鸣器、4 路灰度接口）、
0.96 寸 4 针 I2C OLED（SSD1306）、4 路灰度循迹模块、USB-TTL 串口模块、

> 这正是 KEY_3/KEY_4（原舵机接口）和 LED1/LED2（原红外避障接口）能接出来的原因。

### 1.3 三个必须记住的"坑脚"：PB3 / PB4 / PA15

PB3 = **JTDO**、PB4 = **NJTRST**、PA15 = **JTDI**，复位后归 JTAG 使唤。
**不关掉 JTAG，这三个脚写 GPIO 寄存器纹丝不动**，而且现象特别迷惑：
拿万用表量电压是正常的，写 ODR 就是没反应。

工程里 `board.c` 的 `Board_ReleaseJtagPins()` 已经把这件事做了：

```c
AFIO->MAPR = (AFIO->MAPR & ~AFIO_MAPR_SWJ_CFG_MASK) | AFIO_MAPR_SWJ_JTAG_OFF;
/* SWJ_CFG[2:0] = 0b010：关掉 JTAG，保留 SWD */
```

- 这一步**必须在配置这些引脚的 GPIO 之前**做，否则先写好的模式会被 JTAG 的复用功能盖回去。
  `Board_Init()` 里就是按这个顺序调的，你改代码时别把顺序弄反。
- **关掉的是 JTAG，不是 SWD。** PA13/PA14（SWDIO/SWCLK）照样能连 ST-Link，
  下载、单步、看变量全都不受影响。
- 千万**不要**把 SWJ_CFG 写成 `0b100`（JTAG 和 SWD 全关）—— 写进去以后 ST-Link
  就再也连不上了，只能靠 BOOT0 + 串口 ISP 救回来。
- 受影响的三个功能：**蜂鸣器（PB3）、KEY_1（PB4）、LED2（PA15）**。
  如果这三个里恰好有一个不工作，先怀疑 JTAG 没关干净。

### 1.4 KEY_3 / KEY_4 必须外接

主板上**只焊了 KEY1/KEY2 两个按钮**（就是 PB4/PB5 那两个）。菜单至少要三个键才能用 ——
没有 KEY_3 进不去子菜单，没有 KEY_4 出不来。所以 KEY_3/KEY_4 要自己接：

```
   主板「舵机1」3 针接口            主板「舵机2」3 针接口
   ┌──────────────────┐           ┌──────────────────┐
   │ 信号(PA0) ●──────┼──┐        │ 信号(PA1) ●──────┼──┐
   │ 5V       ●       │  │        │ 5V       ●       │  │
   │ GND      ●───────┼┐ │        │ GND      ●───────┼┐ │
   └──────────────────┘│ │        └──────────────────┘│ │
                       │ │                            │ │
                  ┌────┴─┴───┐                   ┌────┴─┴───┐
                  │  轻触按键 │                   │  轻触按键 │
                  │  KEY_3   │                   │  KEY_4   │
                  └──────────┘                   └──────────┘
```

- **一脚接信号（PA0/PA1），另一脚接接口上的 GND**，两个脚无所谓正负；
- 接口上现成的 GND 直接能用，不用额外拉线到面包板；
- **绝对不要接到 5V 那一针上**。接 5V 的话按键永远读到高电平 = 永远"没按下"，
  严重时还会烧引脚（这两个脚在舵机接口上，旁边就是 5V，接错很容易）；
- 按键用**斜对角**的两个脚一定是一组（同一侧的两个脚内部是连通的，
  接同一侧两个脚等于把引脚直接短到 GND，按键永远"按着"）；
- 不需要外接上拉电阻，`key.c` 里已经配成内部上拉输入了。

> **为什么挑 PA0/PA1？** 因为舵机不用了，这两个脚正好空着，而且就在 3 针接口上 ——
> 插上就能用。改引脚只改 `key.c` 顶部那张 `s_keys[]` 表一处，其它文件一行都不用动。

### 1.5 循迹传感器怎么接

4 路灰度模块的 4 个输出接到 **PB12 / PB13 / PB14 / PB15**，从左到右依次是 S1..S4：

```
              车头方向 ▲
   ┌──────────────────────────────────────┐
   │  S1      S2       S3       S4        │   ← 传感器阵列（模块出厂已排好）
   │  PB12    PB13     PB14     PB15      │
   │  最左     左中      右中     最右      │
   └──────────────────────────────────────┘
```

- **模块的 VCC/GND 一定要接**（从主板上取电即可）。只接信号不接电源，
  输出会一直飘，表现为"四个全黑"或"四个全白"乱跳；
- **极性由模块决定，代码里用 `track.h` 的 `TRACK_BLACK_IS_LOW` 适配**：
  - 填 **1** —— 模块"看见黑线输出低电平"（厂家参考程序里的那种，配的是上拉输入）；
  - 填 **0** —— 模块"看见黑线输出高电平"。
- ⚠️ **本工程实车实测是填 0**（高有效）。装车时按厂家资料先填了 1，结果屏幕上
  黑白正好相反（白底上四个方框全实心），改成 0 就对了。
  **所以别照抄厂家参考程序，以你自己这块模块的实测为准。**
- **判反了不用改线**，只改这一个宏。验证方法：把车拿在手上，用黑纸逐路划过
  S1→S4，屏幕上对应的方框应该逐个变实心、其余三个保持空心；
- **传感器装反了**（S1 跑到最右边）也不用重新焊：把 `track.h` 里的 `TRACK_REVERSE` 改成 1，
  代码会把 bit0↔bit3、bit1↔bit2 对调；
- 为什么配**上拉**输入？有些灰度模块的输出是开集电极的，没有上拉就永远读到 0，
  四个全"压线"，非常误导人；
- **离地高度**：模块离赛道面 1~2 cm 左右最合适。太高了黑线认不出来（全白），
  太低了容易蹭到赛道。

> 电脑端测试（`tests/`）是**极性无关**的：它说的是"这一路压线了/没压线"，
> 再按 `TRACK_BLACK_IS_LOW` 逆变换成电平写进寄存器。所以你把极性宏改成 0 或 1，
> `run_tests.ps1` 都照样全过 —— 测试不会因为你换了块模块就误报固件坏了。

### 1.6 电机怎么接

TB6612 的两个通道接的是**两个电机**，接线在主板 PCB 上已经走好了，一般不用动：

| TB6612 引脚 | STM32 | 接哪个电机 |
|------------|-------|-----------|
| AIN1 / AIN2 / PWMA | PA4 / PA5 / PB8 | **右**电机 |
| BIN1 / BIN2 / PWMB | PA8 / PA11 / PB9 | **左**电机 |

软件里有三个开关可以修方向，都集中在 `motor.h`：

```c
#define MOTOR_A_IS_LEFT     0   /* A 通道是右电机（默认）；如果整车左右反了，改成 1 */
#define MOTOR_A_INVERT      0   /* A 通道转向反了 -> 1 */
#define MOTOR_B_INVERT      0   /* B 通道转向反了 -> 1 */
```

> **两个轮子都装反了** → 改 `MOTOR_A_IS_LEFT`；
> **只有一个轮子反了** → 改对应的 `_INVERT`，或者更省事：**把那个电机的两根线对调**
> （硬件改完一劳永逸，换程序、换车都不用再管）。
> 具体怎么判断见 [第 5 章调参指南](#5-调参指南照着顺序做) 的第 0 步。

### 1.7 LED 与蜂鸣器

两个 LED 接在 **PA12 / PA15**（原红外避障接口），每个串一个限流电阻。
**有两种接法，代码里要用宏选对**：

**接法 A：引脚拉高点亮（源电流）** ← **本工程当前用的**

```
   PA12 ──[220Ω~1kΩ]──▶|── GND        ▶| 是 LED，长脚(正极)在左边
```
电阻接在**引脚和 LED 之间**。对应 `board.h` 里 `#define BOARD_LED_ACTIVE_HIGH 1`。

**接法 B：引脚拉低点亮（灌电流）**

```
   3.3V ──[220Ω~1kΩ]──▶|── PA12
```
电阻接在 **3.3V 和 LED 之间**，LED 另一头接引脚。对应
`#define BOARD_LED_ACTIVE_HIGH 0`。

> **怎么一眼判断自己是哪种？** 电阻接在**引脚**这一侧 → 接法 A（填 1）；
> 电阻接在 **3.3V** 这一侧 → 接法 B（填 0）。
>
> **填错了会怎样？** 灯还是能亮能闪，但**屏幕上的"亮/灭"会和实际灯相反**。
> 改这一个宏重新编译烧录即可，不用重新接线。
>
> **实车验证记录**：本工程一开始按接法 B 填的 0，装车后实测发现屏幕显示"亮"
> 而实际灯是灭的（亮灭反相），于是改成了 1。**如果你换一批灯/换一种接法后
> 又发现反了，把这一项改回 0 就行。**
>
> **LED 有极性**：长脚是正极。接反了不亮，但不会烧。**不要不接电阻**。

蜂鸣器是主板上的**有源**蜂鸣器，接在 PB3，**给高电平就响，不需要 PWM 驱动**。
发车响一声、每跑完一圈响一声，都靠它（`Track_Beep()`）。

### 1.8 串口（USB-TTL）怎么接

```
   Blue Pill          USB-TTL 模块
   ─────────          ────────────
   PA9  (TX)  ──────▶ RXD
   PA10 (RX)  ◀────── TXD
   GND        ─────── GND          ← 必须共地
```

- **TX 和 RX 必须交叉接**。接成 TX-TX 是最常见的错误，表现为完全收不到数据；
- **GND 一定要接**，否则电平没有参考，收到的是乱码；
- **供电**：板子已经由 ST-Link 供电的话，**不要再把模块的 VCC 接上去**，
  两路电源顶在一起可能损坏。要用模块供电就拔掉 ST-Link 的 3.3V；
- **电平**：STM32F1 的 PA9/PA10 是 5V 容忍的，5V 的 USB-TTL 也能用；
  模块上有 3.3V/5V 跳线的话，**拨到 3.3V** 更保险；
- 波特率 **9600**，8 数据位，无校验，1 停止位（8N1）。

### 1.9 上电前检查清单

- [ ] OLED 的 VCC 接的是 **3.3V**，不是 5V
- [ ] OLED 的 SCL 在 PB6、SDA 在 PB7，**没有接反**
- [ ] 循迹模块的 **VCC/GND 都接了**，四个输出在 PB12~PB15
- [ ] KEY_3/KEY_4 接在**舵机接口的信号针 + GND** 上，**没有接到 5V**

### 2.1 工程结构

`1.uvprojx` 已经配好，**双击打开直接 `Build` 就能过**，不需要再做任何设置：

| 分组 | 内容 |
|------|------|
| `User` | 本工程的 10 个 `.c`（main / app / menu / key / oled / oled_font / board / serial / motor / track） |

> 所以不用额外添加 `stm32f10x_gpio.c` 之类的库文件。
>
> ⚠️ **不要**去 `Project → Manage → Run-Time Environment` 里勾 `Device → Startup`。
> 那个组件会引入 `system_stm32f10x.c`，它和本工程的 `keil\system_init.c` 都会定义
> `SystemInit()`，链接会报重复符号。启动文件已经放进工程了，不需要 RTE。

### 2.2 编译结果（实测）

```
Program Size: Code=10684 RO-data=5908 RW-data=136 ZI-data=2928
".\Objects\1.axf" - 0 Error(s), 0 Warning(s).
FromELF: creating hex file...
```

| 项目 | 占用 | 芯片容量 | 余量 |
|------|------|---------|------|
| Flash | Code + RO-data + RW-data ≈ **16.3 KB** | 64 KB | 约 75% |
| RAM | RW-data + ZI-data ≈ **3.0 KB** | 20 KB | 约 85% |

也远低于 MDK-Lite 的 32 KB 代码限制。产物是 `Objects\1.hex`（已勾选 `Create HEX File`），
用 ST-Link 下载即可。

> 数字怎么看：**Flash = Code + RO-data + RW-data**（RW 的初值要存在 Flash 里），
> **RAM = RW-data + ZI-data**。这是 Keil 输出行最容易看错的地方。

### 2.3 用命令行编译

Keil Assistant 插件就是靠这个方式编译的，也可以自己在 PowerShell 里跑：

```powershell
& 'F:\Program Files (x86)\keil5\UV4\UV4.exe' -r 'F:\Stm32\Project\1.uvprojx' `
  -j0 -o 'F:\Stm32\Project\keil_build.log'
```

`-b` 是增量编译，`-r` 是全量重建，`-f` 是下载到芯片。返回码 0 = 无错误无警告。

编译完看一眼日志里的 `Program Size` 和 `0 Error(s), 0 Warning(s)` 就够判断了。

### 2.4 下载到板子

**① 下载器已经配成 ST-Link**，不用再手动设：

| 文件 | 字段 | 值 |
|------|------|-----|
| `1.uvoptx` | `nTsel` / `pMon` | `5` / `STLink\ST-LINKIII-KEIL_SWO.dll` |
| `1.uvprojx` | `Utilities/Flash2` | `STLink\ST-LINKIII-KEIL_SWO.dll` |

Flash 算法是 `STM32F10x_128`（**名字带 128 但没错**：ST 给 STM32F103C8 指定的就是这个，

## 4. 巡线功能详解

这一章是题目 4 的核心。控制器全部在 `track.c` / `track.h` 里，
**没有一行是靠"查表 + 一堆 if-else"堆出来的**，而是「加权偏差 + PD + 元素状态机」。

### 4.1 控制周期与时间基准

| 参数 | 值 | 为什么 |
|------|-----|--------|
| `TRACK_CTRL_MS` | 2 ms（500 Hz） | 比电机机械响应快得多，足够了 |
| `TRACK_SETTLE_TICKS` | 3 次 | 3 × 2 ms = 6 ms 消抖，滤掉毛刺又比任何真实路面变化快 |
| `MAIN_LOOP_MS` | 2 ms | 主循环末尾的延时，决定 `Track_Tick()` 的实际调用频率 |

`Track_Tick()` 每轮主循环都被调用，**内部自己按 2 ms 限频**，所以控制周期是固定的 ——
这一点很重要，PD 的微分项只有周期固定才有意义。

> **为什么时间基准改成了 SysTick 中断？** 圈速计时和丢线防抖都依赖"墙上时间"。
> 刷一次 OLED 要发 1 KB 数据（软件 I2C 大约十几毫秒），那段时间里
> **轮询式的延时是收不到账的，计出来的圈速会明显偏短**。
> 改成 `SysTick_Handler()` 每 1 ms 中断一次推进 `s_ms_tick` 之后，
> 不管主循环在刷屏、在忙等还是闲着，时间都照走。
>
> SysTick 的优先级被特意**放到最低**（`SCB_SHPR3` 写 `0xF0`），
> 这样 9600 波特率的串口接收中断随时能打断它 —— 优先级给高了很容易丢字节。

### 4.2 控制律：加权偏差 + PD

```
error = Σ(位置权重 × 该路是否压线) / 压线的路数      范围 -300..+300
turn  = (Kp × error + Kd × Δerror) / 1000
左轮  = 基础速度 + turn
右轮  = 基础速度 - turn
```

位置权重在 `track.c` 里写死成一张 4 元素表（单位是 1/100 个传感器间距）：

```c
static const int16_t s_pos[4] = { -300, -100, 100, 300 };   /* S1 S2 S3 S4 */
```

`error > 0` 表示**线在车的右边**，要给右转（左轮快、右轮慢）。

> **为什么用加权平均，而不是查表 + 一堆 if-else？** 因为加权平均出来的误差是**连续**的：
> S3 压线是 +100、S4 压线是 +300、S3+S4 一起压线是 +200。
> 离散查表在这三种情况之间是**跳变**的，车会一顿一顿；
> 连续误差才能让车平滑地贴着线走，过弯时也不会冲出赛道。
>
> 四个都压线时平均恰好是 0（车正对着交叉点），符合直觉。

**内轮允许反转**（最多 `-TRACK_REV_LIMIT` = -1500）。这条是直角和折线能不能过
的关键：急弯时内轮倒转 = 原地转，比"外侧快、内侧慢"转得动得多。
外侧仍然钳在满量程 `MOTOR_PWM_MAX` = 7199 以内。

微分项还做了一次一阶低通：

```c
s_dError = ((s_dError * 3) + dRaw) / 4;
```

> **为什么要滤？** 刷一次 OLED 会把某一轮控制周期从 2 ms 拖到十几毫秒，
> 那一拍的 Δerror 会大得离谱，不滤掉车就会莫名其妙猛打一次方向。

### 4.3 八个状态

状态定义在 `track.h` 的 `TrackState` 枚举里，屏幕上显示的是中文名：

| 状态 | 屏幕显示 | 串口 `ST=` | 什么条件下进入 / 干什么 |
|------|---------|-----------|----------------------|
| `TRACK_ST_IDLE` | 就绪 | `IDLE` | 没发车。只更新传感器显示，**一根线都不碰电机** |
| `TRACK_ST_RUN` | 运行 | `RUN` | 正常循迹，跑 PD |
| `TRACK_ST_CROSS` | 十字 | `CROSS` | 四路全黑：**锁定直行** `TRACK_CROSS_MS` = 90 ms 冲过去，同时判要不要计圈 |
| `TRACK_ST_SHARP` | 转弯 | `SHARP` | 只剩最外侧一路（`0x01` 或 `0x08`）→ **原地强转**，直到中间两路重新压线 |
| `TRACK_ST_GAP` | 断线 | `GAP` | 全白且"刚才车基本是正的" → 直行冲刺 `TRACK_GAP_MS` = 170 ms 把缺口冲过去 |
| `TRACK_ST_LOST` | 找线 | `LOST` | 冲不过去 → 朝最后看到线的那一侧原地转着找，超过 `TRACK_SEARCH_TIMEOUT_MS` = 3000 ms 放弃停车 |
| `TRACK_ST_RING` | 圆环 | `RING` | 认出入环口 → PD + 朝环内固定偏置，直到再次看到"丁字"就是出口 |
| `TRACK_ST_FINISH` | 完成 | `FINISH` | 跑完设定圈数，电机停 |

### 4.4 各特殊元素是怎么做出来的（题目 4d / 4e）

**十字** —— 四路全黑时不再听 PD 的，直接"锁定直行"一小段时间。
这是全局最高优先级的事件，因为**十字路口和起跑线的传感器特征一模一样**（都是四路全黑）：
先判要不要计圈，然后一律锁定直行冲过去。
时间 `TRACK_CROSS_MS` 要够车开过整条横线（横线一般比传感器阵列宽），
**太长会在真的十字上"傻冲"一段，太短则刚出横线就又被 PD 带偏**。

**直角 / 折线** —— 只剩最外侧一路压线，说明线急转走了 → 进入强转，
朝那一侧**原地转**，直到**中间两路（`mask & 0x06`）任意一路重新压线**才回到 RUN。
超时 `TRACK_SHARP_TIMEOUT_MS` = 1200 ms 还没咬住线就转去找线。

**断路** —— 全白（丢线）之后要**先分清是哪种全白**，判据是"刚才车是不是基本正的"
（`|s_lastError| < TRACK_GAP_CENTER_ERR` = 130）：

```
刚才车是正的、线突然没了  -> 直线上的缺口，直冲 TRACK_GAP_MS = 170 ms 过去
刚才车正在大角度转弯      -> 是直角/急弯，线拐走了，立刻原地转
```

> **这个顺序不能反！** 一丢线就原地转的话，直线上的小断口会让车原地打转；
> 反过来不分情况地傻冲，直角弯上会先冲 170 ms 直接冲出赛道。

**圆环** —— 入口判据是正好三路压线的"丁字"图形，而且**要连续 3 拍都是这个图形才认**
（避免斜着压线误判）：

```c
0x07 = S1+S2+S3 压线、S4 空  -> 多出来的一支在左边 -> 左环，逆时针绕
0x0E = S2+S3+S4 压线、S1 空  -> 多出来的一支在右边 -> 右环，顺时针绕
```

进环后按 `s_ringDir` 记下**绕环方向**，跑「PD + 朝环内固定偏置 `TRACK_RING_BIAS` = 650」，
**出口判据是再次出现"丁字"**，并且进环后至少待够 `TRACK_RING_MIN_MS` = 700 ms
（防止刚进环就把入口当成出口又冲出来）。兜底：绕超过 `TRACK_RING_TIMEOUT_MS` = 8000 ms
说明判据失效了，回正常循迹，别在环里转到天荒地老。

> **偏置方向千万不能搞反**：环在右边→要一直往右拐→左轮加快、右轮减慢。
> 反了的话车会在环里走直线然后从对面穿出去。

### 4.5 计圈与计时（题目 4b / 4c）

**起跑线判据**：四路全黑。但复杂地图上十字路口遍地都是，它们和起跑线的传感器特征
**完全一样**，所以 `Mark_IsLap()` 设了两道闸门：

```c
static uint8_t Mark_IsLap(uint32_t now)
{
    if (s_markArmed == 0u) { return 0u; }                          /* 闸门 1 */
    if ((now - s_lastMarkMs) < TRACK_LAP_MIN_MS) { return 0u; }    /* 闸门 2 */
    return 1u;
}
```

1. **必须已经离开过黑线**（`s_markArmed`）—— 否则压在一条宽横线上会被连数好几圈；
2. **距离上一次计圈要超过 `TRACK_LAP_MIN_MS`（默认 5000 ms）** ——
   这就是那个"最短圈时"滤波器：**真的跑完一圈至少要这么久，地图中间的十字不可能隔这么近**。

还有一个额外的限制：**只有"正常循迹中"（`TRACK_ST_RUN`）压到四路全黑才算过起跑线**。
绕环、强转、找线途中压到全黑，那是元素本身，不能算一圈。

**计时**（题目 4b 要求"发车自动计时、完成自动停止并显示本圈用时"）：

| 场合 | 行为 |
|------|------|
| `Track_Start()` | 蜂鸣器**先响一声**，然后 `s_startMs = Tick_Ms()` 计时清零、圈数清零 |
| 跑到发车点（第 1 圈，共 2 圈） | **响一声但不停车**，`s_startMs` 重置，下一圈重新计时 |
| 跑到发车点（最后一圈） | 记录本圈用时 → `Motor_Stop()` → 进 `FINISH` → **响一声** |
| 屏幕上 | 第 2 行「用时 12.3s」，一位小数，实时更新 |

> **蜂鸣器为什么要阻塞 45 ms？** 因为巡线途中车正在跑，这 45 ms 里
> **PWM 硬件还在按上一拍的占空比输出，车不会停**；换来的是"响一声"百分之百做得到，
> 不会因为主循环正忙而漏掉 —— **而这一声是有分的**。
>
> 第一圈"响一声且不停车"就是题目 4c 要考的那个点：`Track_OnLapDone()` 里
> `s_lapsDone >= s_laps` 才停车，否则打完招呼接着跑。

## 5. 调参指南（照着顺序做）

> ⚠️ **最重要的一句话**：纯软件的逻辑（状态机、计圈、串口协议、屏幕绘制）
> **已经在电脑上测过 146 项、全部通过**（见[第 7 章](#7-电脑上跑测试不用开发板)）。
> 但**物理常数必须上真赛道调**：
> `TRACK_KP` / `TRACK_KD`、基础速度、`TRACK_LAP_MIN_MS`、
> 圆环的入口图形与偏置、`TRACK_CROSS_MS` / `TRACK_GAP_MS` 这几个时间……

> 赛道宽度和传感器离地高度。**调车占的时间会比写代码多。**

**每一步都要在前一步通过之后再往下走，不要跳步。** 跳步的代价是：
车冲出去了，你不知道是方向反了、传感器反了、还是 Kp 太大了。

### 第 0 步：验证电机转向（**轮子悬空**）

把车架起来，让四个轮子离地。验证方法任选一个：

- **临时改代码**（最直观）：在 `main.c` 的 `for (;;)` 之前插三行，编译烧录。
  上电后两个轮子应该**都朝前转** 1 秒然后停下，确认完把这句删掉：

  ```c
  Motor_SetLR(1500, 1500);    /* 两个轮子都该朝前转 */
  Delay_Ms(1000);
  Motor_Stop();
  ```

- **不改代码**：把车拿在手上（轮子悬空），进「巡线功能」页按 K1 发车，
  看两个轮子转的方向，然后按 K1 或 K4 停车。

判断与处理：

- **两个轮子都朝前** → 通过；
- **只有一个轮子反了** → `motor.h` 里把对应的 `MOTOR_A_INVERT` / `MOTOR_B_INVERT` 改成 1，
  或者（推荐）**把那个电机的两根线对调**，硬件改完一劳永逸；
- **"前进"时两个轮子都往后** → A/B 的左右映射反了，改 `MOTOR_A_IS_LEFT`（0 ↔ 1）。

> **为什么一定要悬空做？** 因为这一步错了后面全错。如果方向反了还放在赛道上，
> 一发车车就往后窜，你会以为是 PD 参数的问题，白调一个小时。
>
> **PWM 是 10 kHz、7200 级**（`TIM4`，PSC=0，ARR=7199），速度值就是**原始 PWM 计数 0..7199**。
> `1500` ≈ 21% 占空比，`1800`（默认基础速度）≈ 25%。

### 第 1 步：验证传感器极性（**车拿在手上，别放在赛道上通电跑**）

进「巡线功能」页，看着屏幕第 1 行的四个方框：

1. 车**悬空**（或放在白纸上）：**四个都应该是空心 □**；
2. 拿一张黑胶带或黑纸，**依次**从 S1 划到 S4，对应的方框应该**逐个变实心 ■**，
   而且**是同一路在变**（划 S1 时不应该 S4 变）。

| 现象 | 原因 | 怎么改 |
|------|------|--------|
| 白底上四个全实心（全"黑"） | 黑白反了，或者模块没接电源/GND | 先查 VCC/GND；确实是反的就改 `TRACK_BLACK_IS_LOW` 为 0 |
| 划 S1 却是 S4 在变 | 传感器阵列装反了 | `track.h` 里 `TRACK_REVERSE` 改成 1，不用重新焊 |
| 怎么划都不变 | 输出没接到 PB12~PB15，或模块没供电 | 查线 |
| 方框一直在抖 | 模块离地太高/太低，或杜邦线接触不良 | 调到离赛道 1~2 cm，压紧线 |

> 这一步对应**题目 4a**：屏幕要能显示全部巡线传感器状态、逐路改变后 1 秒内更新。
> 巡线页是"自定义页面"，`Menu_PageHasValue()` 对 `ops != 0` 的页面**恒返回真**，
> 所以它每 250 ms 无条件重绘一次，远快于题目要求的 1 秒。
> **方框在动 = 这一步的分数已经到手了。**

### 第 2 步：验证按键

1. 主菜单按 KEY_1/KEY_2，箭头上下走、到顶到底会循环；
2. 按 KEY_3 进「LED控制」，按 KEY_1 两个灯亮，按 KEY_4 回主菜单且灯灭；
3. 长按 KEY_4，不管在第几层都直接回主菜单。

> **KEY_1（PB4）、LED2（PA15）、蜂鸣器（PB3）一起不工作** → 十有八九是 JTAG 没关，
> 检查 `Board_Init()` 里 `Board_ReleaseJtagPins()` 的调用顺序（必须在配置这些脚**之前**）。
>
> **完全按不动** → KEY_3/KEY_4 没外接，或者接到了舵机接口的 5V 针上。

### 第 3 步：调直线速度

把车放在直道上，圈数设 1、**把「完成停车」关掉**（这样它跑过头也不会停，方便反复试）。
从默认的 **1800** 开始：

- **跑得起来、又刹得住** → 就这个；
- **太慢、过弯没惯性** → 按 K3 加一档（2400）；
- **快了就冲出赛道** → 降一档（1200）。

可调范围在 `track.c` 里：

```c
#define TRACK_SPEED_DEFAULT     1800u   /* 上电初值                        */
#define TRACK_SPEED_MIN          900u   /* Track_SetBaseSpeed() 的下限      */
#define TRACK_SPEED_MAX         3600u   /* 上限（再大也没有意义）           */

/* 按键能现场切的四个档位。想换成别的速度，只改这一张表就够了 */
static const uint16_t s_speedLevels[] = { 1200u, 1800u, 2400u, 3000u };
```

> 档位表只有这一处。巡线页按 **K3** 和"巡线设置"页里的"速度"项都调
> `Track_CycleSpeed()`，所以两边永远一致 —— 不会出现"菜单里改了、按键那边
> 还是老一套"的情况。

> 现场调速度**不用重新编译**：巡线页按 **K3** 在 4 档之间循环，或者用串口发
> `SPEED 2400`。速度值就是原始 PWM 值（0..7199），屏幕上第 2 行右边就是它。
> 用串口设了一个不在表里的值（比如 2500）也没关系，下次按 K3 会从最慢那档
> 重新开始循环。

### 第 4 步：调 Kp（先把 Kd 当成 0 看）

```c
#define TRACK_KP                5000
#define TRACK_KD                1300
```

误差范围是 ±300（最外侧一路压线时的极限），所以 **Kp = 5000 时最大贡献 ±1500 的转向量**。

| 直线上的表现 | 怎么改 |
|-------------|--------|
| 车画龙，左右来回摆 | **Kp 调小**（5000 → 4000 → 3000） |
| 走不出直线，慢慢偏出去 | **Kp 调大** |

一次改 20%~30%，别一次砍一半 —— 你会分不清是参数不对还是改过头了。
**先在直道上把 Kp 调到"能贴着线走、但还有点小摆"的程度**，摆的那部分留给 Kd 收。

### 第 5 步：调 Kd

| 表现 | 怎么改 |
|------|--------|
| 进弯瞬间冲出去 | **Kd 调大**（提前开始打方向） |
| 出弯后回正慢、发抖 | **Kd 调小** |

**顺序不能反**：Kp 决定"跟不跟得上线"，Kd 决定"稳不稳"。
Kp 还没调好就去调 Kd，等于在给一个错误的系统加阻尼，越调越乱。

### 第 6 步：调元素

到这一步直线应该已经跑得很稳了，再按元素逐个调：

| 元素 | 要调的宏 | 调法 |
|------|---------|------|
| **十字** | `TRACK_CROSS_MS` = 90 | 车在十字上"傻冲"太久 → 调小；刚出横线就被 PD 带偏 → 调大 |
| **直角 / 折线** | `TRACK_REV_LIMIT` = 1500、`TRACK_SPIN_SPEED` = 1500 | 转不过来 → 加大；转过头来回摆 → 减小 |
| **断路** | `TRACK_GAP_MS` = 170、`TRACK_GAP_SPEED` = 1500、`TRACK_GAP_CENTER_ERR` = 130 | 冲不过缺口 → 加长时间；在直角上错误地"傻冲" → 把判据阈值调小 |
| **找线** | `TRACK_SEARCH_SPEED` = 1300、`TRACK_SEARCH_TIMEOUT_MS` = 3000 | 找不到线就停下来了 → 加大超时；找得太久浪费时间 → 减小 |
| **圆环** | `TRACK_RING_MIN_MS` = 700、`TRACK_RING_TIMEOUT_MS` = 8000、`TRACK_RING_BIAS` = 650 | 刚进环就冲出来 → 加大 MIN；贴不住圆弧 → 加大 BIAS；偏置方向反了车会从对面穿出去 |
| **计圈** | `TRACK_LAP_MIN_MS` = 5000 | **量一下自己的赛道跑一圈要几秒，填一个明显小于它的值** |

**单独测某一个元素时**，把「巡线设置 → 完成停车」关掉（或用串口发 `LINE OFF` 关掉计圈），
车就会一直跑下去，你可以反复观察同一段。

> `TRACK_LAP_MIN_MS` 这个值特别容易调错：填太大了，跑完一圈它不认、继续跑；
> 填太小了，地图中间的十字会被当成起跑线提前计圈。
> **判断方法**：跑一圈，看屏幕第 0 行右边的「圈 n/m」什么时候跳。
> 如果在十字路口就跳了 → 这个值调大。

### 第 7 步：跑完整地图

把 4d 的元素（十字、圆环、断路、直角、折线）组合起来跑，观察：

- 屏幕第 0 行的**状态名**是不是在正确的元素上跳（十字 → `十字`、缺口 → `断线`、
  直角 → `转弯`、环里 → `圆环`）；
- 串口 `STATUS` 打出来的 `ST=` / `S=` 和你眼睛看到的是不是一致。

**状态跳错 = 判据错**（改阈值类的宏）；**状态对但车过不去 = 参数错**（改速度、时间、增益）。
这样分开看，比盯着车瞎试快得多。

## 6. 串口协议

波特率 **9600**，8 数据位，无校验，1 停止位（8N1）。上位机发**文本行**就行。

> **不发换行也能用**：很多串口助手默认不勾"发送新行"。程序在收到最后一个字符约
> **60 ms**（`LINK_IDLE_MS`）之后会自动认为这一行结束了，所以两种发法都认。
> 一行的最长长度是 24 字符（`LINK_LINE_MAX`），超了整行丢掉重新同步。

### 6.1 变量 `a`（题目 3）

| 上位机发送 | 单片机行为 | 单片机回复 |
|-----------|-----------|-----------|
| `111` | `a = 111` | 无 |
| `-25` | `a = -25`（**支持负数**） | 无 |
| `0` | `a = 0` | 无 |
| `GET A` | 不改 `a` | `111\r\n`（当前值 + 换行） |
| `abc` 之类的乱码 | 忽略，`a` 不变 | 无 |

- **大小写不敏感**：`GET A` / `get a` / `GETA` / `GET  A` 都认（比较时忽略空格）；
- 数字前面允许有空格和 `+` / `-` 号；
- **一整行必须是合法数字才生效**：`12ab` 会被整行丢弃，不会把 `a` 改成 12；
- 超出 int32 范围的数会被**钳位**到 ±2147483647，不会溢出回绕；
- `a` 是有符号 32 位整数，上电初值 0。

### 6.2 巡线命令（调车专用）

调车的时候人蹲在赛道边、电脑在别处，这套命令就是给这种场景用的：
**不用重新编译烧录，插上 USB-TTL 就能发车、停车、看传感器**。

| 上位机发送 | 单片机行为 | 回复 |
|-----------|-----------|------|
| `TRACK` | 发车（等同于按 K1），蜂鸣器响一声 | 无 |
| `TRACK STOP` | 停车 | 无 |
| `SENSORS` | 读四路传感器状态 | `S=0110` |
| `STATUS` | 把状态打包发回来 | `ST=RUN S=0110 E=-100 SPD=1800 LAP=1 MS=3421` |
| `RING ON` / `RING OFF` | 圆环识别开关 | `RING=ON` / `RING=OFF` |
| `LINE ON` / `LINE OFF` | 起跑线计圈开关 | `LINE=ON` / `LINE=OFF` |
| `LAPS 2` | 设圈数 | `LAPS=2` |
| `SPEED 2000` | 设基础速度（原始 PWM 值 0..7199） | `SPD=2000` |

- **解析时忽略大小写和空格**，所以 `track stop`、`TRACKSTOP`、`Track Stop` 都认；
- `S=0110` 的位序是 **S1S2S3S4**（bit3 打在左边），也就是**屏幕上从左到右看到的顺序** ——
  对着屏幕就能核对；
- `STATUS` 里 `E=` 是当前偏差（-300..+300，丢线时是 -1000）、`LAP=` 是正在跑第几圈、
  `MS=` 是已用时毫秒数。

### 6.3 用 Python 测（就是评分规则里那一轮）

```python
import serial, time

s = serial.Serial('COM3', 9600, timeout=1)   # 改成你的串口号

def send(line):
    s.write((line + '\n').encode())

def read_line():
    s.reset_input_buffer()
    time.sleep(0.05)
    return s.readline().decode(errors='replace').strip()

# --- 题目 3：写 0 / 正数 / 负数，再读回来 ---
def set_a(v):
    send(str(v))

def get_a():
    s.reset_input_buffer()
    s.write(b'GET A')
    time.sleep(0.1)
    return int(s.readline())

for v in (0, 111, -4269):
    set_a(v)
    assert get_a() == v, f'{v} 读回来不一致'
print('三轮回读全部一致')

# --- 巡线命令 ---
send('SENSORS');  print('传感器:', read_line())     # S=0110
send('STATUS');   print('状态  :', read_line())
send('SPEED 2000'); print(read_line())             # SPD=2000
send('LAPS 2');     print(read_line())             # LAPS=2
send('RING OFF');   print(read_line())             # RING=OFF
send('TRACK')                                       # 发车（蜂鸣器响一声）
time.sleep(3)
send('TRACK STOP')                                  # 停车
```

> **为什么串口是用中断收、而不是在主循环里轮询？** 刷新一整屏 OLED 要十来毫秒，
> 比 9600 波特率下一个字节的时间（约 1 ms）长得多。靠主循环轮询的话，
> 屏幕一刷新就会丢字节。USART1 中断把收到的字节塞进环形缓冲区，主循环慢慢取，
> 一个字节都不会丢。`Serial_RxOverruns()` 可以查因为缓冲区满而丢掉的字节数。

### 8.3 源码的编码和中文注释

**所有 `.c` / `.h` 都是 UTF-8 无 BOM、LF 换行，注释是中文。**

- **在 VSCode 里看**：默认就是 UTF-8，中文注释显示正常，不用设置；
- **在 Keil uVision 里看**：Keil 在中文系统上默认按 ANSI（GBK）读源文件，
  中文注释可能显示成乱码 —— **这只影响显示，不影响编译**。想让它正常显示：
  `Edit → Configuration → Editor → Encoding` 选 `Encode in UTF-8`。

> ⚠️ **`.ps1` 脚本必须存成 UTF-8 *带 BOM***，这一点和 `.c` / `.h` **正好相反**。
> 原因是 Windows PowerShell 5.1 在没有 BOM 时会按 ANSI（GBK）读脚本文件，
> 脚本里的中文提示和中文注释就会变成乱码，甚至直接报语法错误。
> `tools\` 下的三个脚本都是 UTF-8 with BOM 保存的。

> **为什么菜单文字不直接写中文字符串，而是写成 `{ CN_KONG, CN_ZHI, 0 }` 这种码点数组？**
> 就是为了不受编辑器编码影响：不管 Keil 把源文件当成 UTF-8 还是 GBK，
> 编译进单片机的字节都一样，屏幕上不会出现乱码。中文注释没有这个顾虑，
> 因为注释根本不进二进制。

### 8.4 怎么加一个汉字

汉字点阵是脚本生成的，**源文件里不出现中文**，汉字用 Unicode 码点表示
（例如 `CN_KONG` 就是 `0x63A7`，即"控"）。当前字库有 **90 个**汉字。

1. 打开 `tools/genfont.ps1`，在 `$Cjk` 表里按**码点从小到大**的位置插入一行：
   `@(0x8BBE, 'CN_SHE', 'she = set up')`（第一个是该字的 Unicode 码点）；
2. 运行脚本重新生成 `User/oled_font.c` 和 `User/oled_font.h`：

   ```powershell
   powershell -File tools\genfont.ps1
   ```

   脚本最后会打印 `CJK glyphs: 90  ASCII glyphs: 95`，以及有没有渲染成空白的字。
   输出路径就是 `F:\Stm32\Project\User`（早期版本这里写死成上一级目录，
   生成的文件会跑到 `F:\Stm32\User` 去，**这个 bug 已经修掉了**）；
3. 在源码里直接用 `CN_SHE` 拼字符串。

> `$Cjk` 表**必须保持码点升序**：`Font_FindCjk()` 用的是二分查找，顺序错了就找不着字。
>
> 查汉字码点：Windows 计算器切到"程序员"模式，选"Unicode"输入汉字即可看到；
> 或者用 `[char]0x8BBE` 在 PowerShell 里反查。

### 8.5 怎么加一个菜单项

菜单项四个字段分别是 `{ 文字, 子菜单, 按键3的动作, 右侧实时值 }`，不用的填 `0`：

```c
static const uint16_t T_MYITEM[] = { 'T', 'E', 'S', 'T', 0 };

static const MenuItem kMyItems[] = {
    { T_MYITEM, 0, My_Action, 0 },      /* 按键3 调用 My_Action() */
    { T_BACK,   0, Menu_Back, 0 }
};
static const MenuPage kMyPage = { kMyItems, 2u, 0 };
```

再把 `&kMyPage` 挂到上一级菜单某个菜单项的第二个字段上即可。
**菜单项超过 4 项会自动滚动**，不需要额外处理。

如果要做的是**控制面板**（像 LED控制 / 信息显示 / 巡线功能 那三页），
就在 `MenuPage` 的第三个字段填一个 `MenuPageOps`（`onKey` / `onDraw` / `onLeave`），
引擎会把按键和绘制全部交给它，`items[]` 列表被忽略。
`onLeave` 特别适合做"退出时必须停车/关灯"这种收尾 —— 不管用户是正常返回
还是长按 KEY_4 溜出去，都会走到它。

## 10. 常见问题对照表

### 10.1 电机与运动

| 现象 | 可能原因 | 怎么查 / 怎么改 |
|------|---------|----------------|
| **某个电机转反了** | 该电机两根线接反 | 悬空验证（第 0 步）：改 `MOTOR_A_INVERT` / `MOTOR_B_INVERT`，**或**把那个电机的两根线对调 |
| **"前进"时车往后走** | A/B 的左右映射反了 | 改 `MOTOR_A_IS_LEFT`（0 ↔ 1） |
| **车完全不动，但屏幕正常** | ① 初始化顺序错（`Motor_Init()` 在 `Board_Init()` 之前，GPIO 时钟没开）<br>② PB8/PB9 没配成**复用推挽**（定时器在数、CCR 在变，引脚不理你）<br>③ 电池没电 / TB6612 的 STBY 没拉高<br>④ 在 `STATUS` 里看 `ST=IDLE` —— 根本没发车 | ① 按 `main.c` 的顺序：`Board_Init()` → `Motor_Init()`<br>② 看 `motor.c` 里 `GPIO_CFG_AF_PP_50M`<br>③ 量电机供电电压<br>④ 按 K1 或发 `TRACK` |
| **车一动就冲出去 / 全速跑** | 基础速度给太大 | 按 K3 降到 1200，或发 `SPEED 1200` |
| **以为车在跑、其实速度是 0** | `Motor_Stop()` 之后没发车（`Track_IsRunning()` 为假时 `Track_Tick()` 只更新传感器、不碰电机） | 看串口 `STATUS` 的 `ST=`，`IDLE` 就是没发车；按 K1 或发 `TRACK` |

### 10.3 按键与显示

| 现象 | 可能原因 | 怎么查 / 怎么改 |
|------|---------|----------------|
| **按键完全没反应（4 个都不动）** | ① `Key_Init()` 没在 `Board_Init()` 之后调用<br>② 按键没接 GND | ① 看 `main.c` 的顺序<br>② 量按下时引脚是不是 0V |

| 现象 | 可能原因 | 怎么查 / 怎么改 |
|------|---------|----------------|

| **在圆环里走直线从对面穿出去** | `TRACK_RING_BIAS` 的**方向反了** | 检查 `s_ringDir` 的左右判断和偏置的正负号 |
| **刚进环就冲出来** | `TRACK_RING_MIN_MS`（700）太小 | 加大 |
| **在环里转到天荒地老** | 出口判据失效，又没到超时 | 检查出口的"丁字"图形；`TRACK_RING_TIMEOUT_MS`（8000）是兜底 |
| **圆环被当成普通弯道** | 圆环识别被关了 | 巡线设置 →「圆环」应显示`开`，或发 `RING ON` |
| **计圈错了：地图中间的十字就算一圈（false lap counting）** | `TRACK_LAP_MIN_MS`（5000）太小 | **量一下自己赛道跑一圈几秒**，填一个明显小于它的值。判断方法：看屏幕「圈 n/m」在哪个位置跳 |
| **跑完一圈不计圈、继续跑** | `TRACK_LAP_MIN_MS` 太大 | 调小 |
| **压在起跑线上被连数好几圈** | `s_markArmed` 那道闸门失效 | 检查 `Track_Start()` 里有没有把 `s_markArmed` 清 0；正常情况下必须**先离开黑线**才认下一次 |
| **绕环 / 强转 / 找线途中被算成一圈** | 计圈条件被放宽了 | 代码里限定只有 `TRACK_ST_RUN` 状态下的全黑才计圈，别改掉这个判断 |
| **跑完不停车** | 「完成停车」被关掉了 | 巡线设置 →「完成停车」应显示`开`；或「系统设置 → 恢复默认」 |
| **发车不响（buzzer silent）** | ① **PB3 是 JTDO，JTAG 没关**（最常见！）<br>② 蜂鸣器是有源还是无源搞错了（本项目要**有源**，给高电平就响）<br>③ `Board_BeepInit()` 没调 | ① 查 `Board_ReleaseJtagPins()` 的调用顺序<br>② 量 PB3 平时是低、发车瞬间变高<br>③ 看 `Board_Init()` |
| **蜂鸣器一直响，停不下来** | 发车/计圈的提示音是**故意阻塞 45 ms** 的一短声；如果它一直不停，说明关的那一句没执行 | 看 `Track_Beep()` 里 `Board_BeepWrite(0u)` 有没有被跳过；单独测「拓展功能 → 蜂鸣器测试」是不是响 120 ms 正常 |
| **跑完一圈听到的是"一长声"** | 这是对的：最后一圈在 `Track_OnLapDone()` 里**只响一声**，但这一声和紧接着的停车动作几乎同时发生，听起来会像一声拖长 | 不需要改 |
| **按 K4 返回后车还在跑** | 正常情况不会：`TracePage_Leave()` 一定会调 `Track_Stop()` | 如果真发生了，检查那一页是不是被改成了普通列表页（`MenuPage` 的第三个字段 `ops` 丢了，`onLeave` 就不会被调用） |

### 10.5 串口

|------|---------|----------------|
| **完全收不到数据** | TX/RX 接成 TX-TX（没交叉） | PA9→模块 RX，PA10←模块 TX |
| **收到乱码** | ① 没共地<br>② 波特率不是 9600 | ① 接 GND<br>② 两边都设 9600 8N1 |
| **发命令没反应** | ① 大小写/空格其实没关系，所以先查是不是**没发换行也没停顿**<br>② 行里有别的字符 | ① 每行末尾加 `\r\n`，或者发完停 100 ms<br>② 一行最长 24 字符 |
| **`SENSORS` 回的值和屏幕不一致** | 串口读到的是 `s_stable`（消抖后），和屏幕用的是同一个值 | 不应该不一致；若真不一致，看是不是两个上位机在同时发命令 |
| **`GET A` 返回空** | `reset_input_buffer()` 之后没等 | 按第 6.3 节的 Python 例子，`time.sleep(0.1)` 再读 |

## 11. 一些实现上的取舍（为什么这么写）

- **OLED 只在需要时重绘**：刷一次要发 1 KB 数据（软件 I2C 约 10 ms）。
  按键后立即重绘（`Menu_Invalidate()`），带实时数值的页面每 250 ms 重绘一次；
  巡线页是自定义页面，恒按 250 ms 重绘，所以传感器状态和用时都是活的。
- **晶振没起振也不死机**：`Clock_Init()` 里每一步都有超时，任何一步失败就退回内部
  8 MHz HSI 继续跑，菜单照样能用；「关于本机」里的主频显示的是**真实频率**
  （`Board_ClockHz()`），不会硬编码 72 MHz 去骗界面。
- **时间用无符号相减算差**：`(uint32_t)(now - start)`，这样 `Tick_Ms()` 49.7 天回绕时
  结果依然正确。全工程的时间比较都用的这个写法。
- **`Motor_SetLR()` 里 pwm = 0 是"自由停止"而不是"刹车"**：巡线过程中速度过零是常事，
  每次都刹车会让车一顿一顿的。要急停请显式调 `Motor_Brake()`。
- **传感器消抖放在控制里，不放在显示里**：控制用的是 `Track_ReadStable()`，
  屏幕显示的也是它 —— 保证"看到的"和"控制的"永远是同一份数据。
- **换引脚只改一处**：按键引脚只在 `key.c` 的 `s_keys[]` 里出现，
  循迹引脚只在 `track.h` 的 `TRACK_PIN_S1..S4` 里出现，
  LED/蜂鸣器只在 `board.h` 的 `BOARD_LED*_PIN` / `BOARD_BEEP_PIN` 里出现。
  改一处，`Key_Init()` / `Track_Init()` / `Board_LedInit()` 就会去配置新引脚。
